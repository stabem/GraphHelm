# Recovered: the destroyed `THE UNIFICATION (C)` block from `SLOT.lock`

**Why this file exists.** The prose in `D:/graphhelm-slot/SLOT.lock` was reported as *"already
moved"* to `ENV-DECISIONS.md` when the lock was rebuilt as a one-line possession file. It was not
moved at the time — the destination's mtime preceded the rebuild and greps for the block's own
strings returned zero there.

**CORRECTION, measured after the fact and left visible rather than edited away: the substance was
NOT lost.** The destination has since been restored, and by grep for distinctive substance —
`NAMED IN THE COMMAND`, `cross the tool boundary`, `switches itself off`, `where the hand acts`,
`LATENT`, `ls-remote` — **all six are present, 1 each.** My earlier figure of *"~62 of 84 lines
lost"* came from an **exact-line diff**, and that is the wrong instrument for recovery: **a
legitimate restore REFORMATS, so line-diff over-reports loss.** The right instrument is distinctive
substance.

**And the cost of that false alarm is the one that killed my own pre-flight check earlier today:** a
recovery verification that cries loss over text that exists **trains everyone to ignore recovery
verifications.** The finding was another agent's; I confirmed it with strings they did not use.

**Provenance of this copy, stated so nobody treats it as authoritative beyond what it is.** I read
`SLOT.lock` while it was 2962 bytes and printed the first ~40 lines into my session. What follows is
that capture, verbatim. **It is a partial recovery**: it covers the three blocks I printed and
nothing below them. Another agent preserved the first 25 lines independently; the union of the two
captures is larger than either.

**And the durable copy was never the lock.** The substance of all three blocks lives in my own
memory files — the unification in `shell-tooling-traps`, the ED-9 correction in
`baseline-boundaries`, the detector consequence in `gate-prices-the-wrong-unit`. The lock was a
bench; the notes are the record. That is why the loss is recoverable at all.

And the `export` cost did not come from anyone not knowing the fact -- it is written in the tool's

=== CORRECTION to ED-9's leftovers: do not patch a question that should FALL (C, against himself) ===
He had proposed pasting `git fetch origin main` before the distance line. He withdrew it, and the
reason generalises: **that hardens a question neither surviving formulation needs to ask.**
    as MEASURER    -- `HEAD == the sha I will cite` never consults `origin/*` at all, so there is
                      no fetch that can be stale.
    as ADJUDICATOR -- the ref is inside the command, so the read is anchored to what the command
                      names.
**Neither needs the fetch, so neither has the hole.** A patch that makes a check "safe if everyone
remembers" is worse than a formulation that needs no remembering. **Anchoring cuts the coupling; a
detector only watches it.**
The distance line stays as a SIGNAL that ages -- with the thirteen measurements and the date -- and
never as a verdict. And the question "am I current with the remote?" does not disappear: it changes
owner and instrument. It decides a REBASE, never validates a measurement, and its ground truth is
`git ls-remote origin main`, which talks to the remote instead of trusting the local mirror.
Keep the fetch hole labelled **LATENT, not active** -- a real mechanism whose two ends happen to
match today. That is the only record form that invites neither alarm nor filing-away.

=== AND THE DESIGN CONSEQUENCE THAT DECIDES WHETHER A DETECTOR IS WORTH BUILDING ===
A detector with an acceptable false-positive rate is not a weaker detector -- **it is a detector
that switches itself off over time.** The tolerable false-positive rate is not traded against
detection rate; it is traded against the detector's SURVIVAL. One with 5% false positives and one
real case a month is dead before the first real case arrives.

## The class this loss belongs to, which is the same one the block was about

**"Already moved" is a conclusion, and nobody checks a conclusion.** The rebuild recorded a
completed task; the destination was never greped. **The loss registers as work done** — which is
precisely why it survives review.

The cheap check that would have caught it is the one this whole day kept arriving at: **grep the
DESTINATION for a string only the moved text contains, before declaring the move.** A move is not
done when the source is gone; it is done when the destination answers.

**Two independent partial captures exist and neither owner knew the other had one.** If prose is
worth moving, it is worth having a durable home before the move — not after.
