# Approved decision register

This document consolidates the product decisions already made. They are normative for version 0.1 of the specification.

| ID | Theme | Decision |
|---|---|---|
| D-001 | Topology | Local Studio as control plane; runtime and data on the user's VPS. |
| D-002 | VPS connection | Existing VPS connected via SSH; installation and updates via Docker. **Exception proposed in ADR-037 (#663): the host-side install/update/backup/restore lifecycle may be systemd-managed, as PR #595 ships it. Not in effect while #595 is open; the ADR is accepted with #595's merge.** |
| D-003 | Autonomy | Total autonomy governed by the harness; no mandatory approval between phases. |
| D-004 | Scope | Generalist agent operating system, not just a coding tool. |
| D-005 | Harness | Harness synthesized per task from atomic capabilities; no fixed domain-specific pack. |
| D-006 | Mandatory rules | Deterministic Policy Engine enforces invariants and gates according to risk signals. |
| D-007 | Agents | Ephemeral agents are synthesized with contracts and registered capabilities. |
| D-008 | Agent persistence | Useful agents are saved to the Project Agent Registry and can be reused. |
| D-009 | Agent memory | Limited, auditable memory, with evidence, confidence, validity, and expiration. |
| D-010 | Project truth | Three layers: Evidence/Event Store, Project Knowledge Graph, and Living Documentation. |
| D-011 | Dreams Engine | Total governed autonomy over knowledge, documents, agents, skills, and indices. |
| D-012 | Dreams and code | Dreams does not alter code directly; it creates a normal, substantiated task for the Graph Engine. |
| D-013 | Isolation | Adaptive isolation Tier 0–3, escalated according to discovered risks. |
| D-014 | Models | Universal Model Gateway with BYOK, direct APIs, aggregators, native runtimes, and local models. |
| D-015 | Subscriptions | Official connection to ChatGPT/Codex and Claude/Claude Code accounts when supported by the provider. |
| D-016 | Subscription fallback | When the subscription limit is reached, pause; do not automatically spend via BYOK/OpenRouter. |
| D-017 | Context | Layered Context Compiler with node-specific capsules and justified expansion. |
| D-018 | Runtime graph | Adaptive, versioned graph, altered only by the Graph Governor. |
| D-019 | Sovereignty | The user can pause, remove gates, skip phases, and connect directly to deploy. |
| D-020 | Agent replacement | A replacement agent never starts automatically after manual intervention; it requires confirmation. |
| D-021 | Ghost nodes | Proposed expansions appear as transparent nodes without consuming tokens before approval. |
| D-022 | Modes | Autopilot, Supervised, and Manual Graph, switchable during execution. |
| D-023 | Node editor | Full editor: objective, prompt, model, context, skills, tools, contracts, gates, and retries. |
| D-024 | Editing a saved agent | Node changes apply only to the current execution; promotion requires an explicit action. |
| D-025 | Editing during execution | Visual changes apply immediately; operational changes enter a transactional Graph Draft. |
| D-026 | Chat | Contextual Command Router; operational mutations become drafts pending confirmation. |
| D-027 | Hierarchy | Workspace → Project → Subproject, with selective inheritance of context and policies. |
| D-028 | Collaboration | Single-user first, but identity, authorization, and audit ready for teams. |
| D-029 | Open source | Framework, Runtime, and Studio fully open source; no essential function closed. |
| D-030 | Licensing | MIT, single license. Supersedes the earlier AGPLv3-plus-commercial plan: that design existed to hold a commercial lever, and the owner chose adoption over the lever. |
| D-031 | Contributions | No CLA. Inbound equals outbound under MIT, so there is nothing left for a contributor agreement to grant. Supersedes the ICLA/CCLA plan, which existed only to enable commercial relicensing. |
| D-032 | First slice | Complete developer-first vertical slice, without limiting the generalist architecture. |
| D-033 | Current state | Produce full documentation before any implementation. |
| D-034 | Name | GraphHelm is the product name selected for development, subject to legal clearance and namespace reservation before public launch. |
| D-035 | Event and evidence persistence | The replay-safe Event Journal is append-only; sensitive evidence is encrypted and kept separate, may undergo auditable erasure under explicit authority/policy, and never makes canonical replay dependent on plaintext. |
| D-036 | Safe persistence projection | The authoring graph and the `PersistedGraphVersion` are distinct representations: the Governor deterministically externalizes free-form content as encrypted Evidence, keeps only safe topology inline, and computes semantic identity from the ordered content digests. Required content that is deleted or unavailable blocks execution. JSONL and PostgreSQL immediately adopt the new format, with no legacy compatibility layer whatsoever (`no legacy compatibility layer`): pre-release internal compatibility, legacy importers, and the intermediate `1.1.0` release are removed, and the public `1.0.0` baseline is rebuilt. Persisted diagnostics contain no filesystem/source path or dynamic prose; the only permitted locator is a domain-scoped JSON Pointer limited to registered GraphHelm contract roots. The limited persistence waiver replaces the previous internal draft. |
| D-037 | Authoring paths in the safe projection | The Foundation contract allows paths in context source scopes, permission scopes, and isolation writable lists. The persisted projection never copies this plaintext: each position is mandatory, `restricted`, ordered Evidence, semantically hashed under one of the closed types `ContextPath`, `PermissionPath`, or `IsolationPath`. The previous eight-position enum was incomplete and is replaced by eleven positions. Since the product has not yet been published, the sole public `1.0.0` baseline is corrected in place, with no alias, translation, intermediate release, or legacy branch. |
| D-038 | Hand-rolled HMAC and base64 instead of the planned pinned crates | The plan fixed `hmac = 0.13.0` and `base64 = 0.23.1` as exact-pinned dependencies. Neither is declared; HMAC-SHA-256 and base64url are implemented in-tree. This deviation is accepted and recorded rather than reversed. Both implementations are small, closed, and now pinned to the standards' own vectors, and swapping the HMAC late would change the byte output that authenticated receipts, checkpoints and the revocation journal already depend on. The in-tree HMAC additionally keeps its inner and outer pads, derived subkeys and intermediate digests in `Zeroizing`, which a crate boundary would not guarantee. Adopting the pinned crates remains an open option and must be a deliberate, separately verified change, not a silent substitution in either direction. |
| D-039 | Chat-first operation via an official MCP server | GraphHelm ships an MCP server as a first-class surface, so a coding agent chat — Claude Code and Codex both speak MCP — can start, observe, signal, approve, pause, resume, and cancel executions from inside the conversation. It is an adapter over the Public Runtime API and never a second operational path: every Runtime read, mutation, and privileged capability used by chat is available identically through the API and CLI. Schema-bound local advisory artifacts may be authored without creating Runtime authority. Host-specific packaging (Claude Code plugin/skill, Codex MCP configuration) wraps the one server; the contract is the MCP server, not the wrapper. |
| D-040 | The monitor precedes Studio | The first UI is a local, read-only monitor page served by the Runtime itself — executions, node states, triage view, events tail — reading only the Public Runtime API so full Studio later replaces it without migration. It contains no mutating action: a UI that can mutate is Studio, and Studio (chat, canvas, the organizing web app) remains its own later milestone, optional. |
| D-041 | Journey-Proven Development and one extension model | Development assurance starts from the complete user journey: promises become typed observation obligations, and the harness selects the smallest proof methods adequate to their risk. Unit, property, integration, concurrency, and browser tests remain available but no one ritual is universal. Missing observation capability is a typed `OBSERVER_MISSING` refusal; later successful retries preserve the initial failure and lineage. A `flaky_pass` is never JPD-proven; it remains unresolved or requires a blocker-local owner waiver. Skills, observers, evaluators, agents, schemas, graphs, and host adapters are contributions of the existing versioned `Extension` model, never a second plugin format. JPD orchestration skills and host wrappers call GraphHelm only through public CLI, MCP, or HTTP contracts; executable contributions use their declared Extension and Tool Broker protocols and never import core internals. |
| D-042 | Containment-safe code-index provider boundary | GraphHelm may decode bounded, recorded `structuredContent` from a code-index provider without treating that decoder as a live MCP connection. Live provider retrieval requires a broker-managed MCP SDK session over an immutable, digest-pinned index snapshot copied into Tier 1, with a verified executable and `CBM_CACHE_DIR` confined to that sandbox. Index construction and retrieval are separate operations. Until those contracts exist, live retrieval fails closed as unavailable; GraphHelm never exposes the host provider cache, invokes the provider directly, auto-indexes, or invents invocation or executable identity absent from `ToolCallRecord`. **AMENDED by ADR-034 / D-048 on ONE axis only: the maintained-SDK requirement is conditionally lifted for framing that stays bounded by the guard ADR-034 requires — three fixed messages, no capability advertised and none read, one process per call. Every other clause of this decision stands unchanged. This amendment TAKES EFFECT when ADR-034 is accepted, which ADR-034 conditions on its guard landing; until then D-042 stands in full.** |
| D-043 | Execution accounting uses event identity, never invented snapshots | A durable execution-accounting receipt binds the exact persisted `execution_started` event by closed binding kind, event-envelope schema identity/version, event ID/hash, repository scope, and the full producer actor `{type,id}`. It does not reuse `ArtifactBinding`, because an execution event owns no repository/index `SnapshotBinding` and GraphHelm must not manufacture one. Provider-reported input/output are measured only when reported; compiled input and provider-total input remain unavailable until complete producers exist. Every token integer is bounded to the JSON interoperable safe-integer maximum on write and read. |
| D-044 | Verdict-aware retry policy fails closed | A completed non-zero tool exit is terminal by default and becomes retryable only through explicit `retryOn: [tool_exited_non_zero]`; `doNotRetryOn` explicitly preserves that terminal verdict. Tool timeout remains retryable because no verdict completed. Durable `HostError` codes are terminal because the persisted record lacks the `ErrorKind` required for a deterministic transient/permanent split. `retryOn` and `doNotRetryOn` must be disjoint: overlap is invalid and is refused deterministically before any node effect, with stable evidence and terminal settlement instead of a stranded `Ready` node or running execution. GateCheck semantics are unchanged. |
| D-045 | Retrieval coverage is an immutable sidecar receipt | `RetrievalCoverageReceipt@1` records one Runtime-validated structural-index attempt without mutating the pre-execution `RetrievalPlan` or adding a new `DevelopmentKind`. It binds the exact plan, step, query, scope, snapshots, provider capability, durable Tool Broker record, coverage, pagination, limits, canonical hits, fallbacks, and canonical digest. The first producer is a deterministic fake behind the brand-neutral `StructuralCodeIndex` port. Live MCP and native indexing remain unavailable under D-042. **AMENDED by #219 on the source-fallback clause ONLY: bounded source fallback is available at the retrieval compile layer through `compile_plan_composed_against`, which consults a `BoundedSourceSearch` channel SUPPLIED BY THE CALLER (the port in `core/runtime/src/ports.rs`; the channel is injected, so `source_fallback_available()` = `true` states that the PATH exists in the runtime, not that a producer is present). Licensed exclusively by a non-complete coverage state, behind the same snapshot-freshness, escape and declared-limit checks as the index’s own hits, with the channel’s typed failure returned beside the outcome and coverage never promoted. The amendment rests on a measured finding, not preference: required evidence living in non-code files is unreachable through `StructuralCodeIndex` at ANY query, because the provider filters non-construct nodes by design — so the compiler grew a bounded second channel rather than the corpus getting easier questions. The receipt itself still records fallback as unavailable — its vocabulary has no success state — and receipt-boundary integration (scope binding, outcome recording) is tracked in #655; until that lands, a composed claim is compile-layer evidence only, never receipt evidence. The workspace-backed implementation of the port (`WorkspaceSourceChannel`) is delivered by #622. The base plan compiler (`compile_plan`/`compile_plan_within`) already has a non-test consumer — `tools/development-benchmark` (`src/lib.rs`); only the COMPOSED path (`compile_plan_composed_against`) awaits its production consumer, tracked in #724; #223/#224 (plan Tasks 007/008) closed on 2026-08-30 and 2026-08-24 without bringing one, measured in #722. The amendment, its alternatives and the measured finding are recorded in ADR-035, which also names the contradiction it resolves in accepted ADR-031 (whose receipt-level and reindex-axis claims stand unchanged). **NORMATIVE: ADR-035 was accepted 2026-09-02 (by the Orchestrator on the owner’s delegated authority; technical gate: K’s review of #608), so this amendment is in effect. The code fact `source_fallback_available()` = `true` states that the compile-layer fallback PATH exists in the runtime (the channel is caller-injected); the composed path’s production consumer is tracked in #724 (#223/#224 closed without it, see #722).** Every other clause of this decision stands unchanged.** |
| D-046 | Memory lifecycle is two independent axes, not one; a frozen release's derived metadata is re-derived in place, never versioned, only with an exhibited control | Durable memory splits semantic validity (`candidate\|validated\|contradicted\|deprecated\|expired`, already normative for `memory_record.status` in the Data & Protocols reference) from publication state (`unpublished\|proposed\|published\|withdrawn`), replacing the single `provisional\|published\|superseded\|withdrawn` axis task-004 shipped ahead of this decision. `superseded` is removed as a state: superseding is a `supersedes` relationship to an immutable successor, and the predecessor's own semantic axis moves to `deprecated` or `contradicted` by the caller's stated reason, never inferred. Withdrawal moves only the publication axis and never deletes or rewrites the journal; erasure is a distinct, already-existing mechanism (D-035) and is orthogonal to both axes. A handoff into a scope without capture opt-in is refused by name at the transition site, never silently allowed. Separately, and answering #220's own "corrected in place or versioned" question for any checked-in `1.0.0` artifact: authored content in a frozen release never changes; derived metadata found wrong (the `event-envelope` catalog digest, #508/PR #511) is re-derived in place, with the guard updated in the same commit — legal only when the correction's own diff exhibits a control proving it touched no authored file, never on the editor's unverified say-so. |
| D-047 | Countersign clearance is signed, verified at append, never in the fold | `ClearanceVerifier::Countersign` gains a mandatory asymmetric signature (signing capability strictly separate from verifying — a shared-secret MAC would let any verifier forge) binding the signer to the exact claim instance (stream identity, `claim_seq`, journaled evidence digest), decided while zero Countersign events exist in any journal so the wire change costs no migration. Verification happens at append time in the command layer against per-identity public keys held as verified children of the anchored keyring directory (reusing `open_and_verify`/`verify_child_identity`, per #161's custody decision — never a widened `KeyringDocument`); failure refuses with `signature_unverifiable`, giving the ninth frozen refusal code its producer in the same change that creates the first Countersign producer, exactly as the #527 trap enforces. The fold keeps comparing journaled data to journaled data — no key material or cryptography in replay, so replay stays a pure function of the log. The retire-the-refusal alternative was rejected by the reversibility asymmetry: retiring now and signing later pays a journal migration; signing now pays nothing. (ADR-033, #529.) |
| D-048 | The contained producer may hand-roll bounded framing, and the bound is a guard | ADR-026's revisit trigger governs GROWING the hand-rolled layer toward resources, push notifications, `structuredContent` results or a non-stdio transport -- not consuming a richer payload through the strict bounded decoder ADR-028 already permits. The contained producer's framing is three fixed messages that advertise no capabilities and read none -- `retrieve` consults only the reply bearing id 2, so the server's advertisement never reaches this client -- one process per call, and no reused server code, so the layer did not grow. D-042's and ADR-028's maintained-SDK clause is AMENDED along that one axis and waived along none: the broker-owned session, pinned snapshot, verified executable and confined cache stand unchanged. The amendment is conditional on a guard pinning the request set, so a fourth message, a negotiated capability, a second tool or a non-stdio transport breaks the build and reopens ADR-034 rather than relying on anyone remembering. A reply the decoder cannot read refuses as `Unavailable`, never a partial belief. **NOT YET IN EFFECT: ADR-034 is `proposed` and conditions its own acceptance on the guard landing. This row records the decision; it becomes normative when ADR-034 is accepted.** |
| D-049 | The envelope's top-level union is deliberately unprovable, and the gap is pinned in both directions | `one_of_branches_are_provably_disjoint` decides a `oneOf` from the branches it is handed. `event-envelope`'s top-level `/oneOf` is genuinely disjoint, but its disjointness is established by a CONJUNCTION OF THREE SEPARATE PLACES -- the envelope's sibling `"type": "object"`, its sibling `required` naming `kind`, and the `$ref` to `$defs/eventKind` whose branches require `["type","data"]`. Its 44 branches declare no `type` and no `required` of their own, and their discriminator sits two levels down at `kind.type`. Proving it needs propagated type, propagated `required`, a nested discriminator, and a `$ref` hop: four widenings, each with its own way to be silently unsound, adopted under the deadline of a blocked slice. So it is NOT attempted, and the whole set of unions this prover cannot decide is pinned in `tests/union_provability.rs`, EACH WITH ITS CLASS, because the classes are not interchangeable and a maintainer reading the wrong one attempts a widening that cannot work: **A** (7) is `X`-or-`null` with a `$ref` branch, decidable by a `$ref` hop; **B** (4) inherits its constraints from the enclosing schema, decidable only by the reopening door named below; **C** (1, `agent`) is the `exactly one of` idiom and is DELIBERATELY not disjoint, so no widening will ever move it and nothing is wrong with it; **D** (1, `node`) is disjoint by EXCLUSION -- `additionalProperties: false` forbidding the property its sibling requires -- a proof this prover does not model and which none of the other remedies reaches. Classes are assigned by POSITIVE predicate: a union matching none is marked `?` and investigated, never folded into the nearest neighbour, because the first version of this taxonomy used a residual bucket and it absorbed `node` wrongly. Asserted in BOTH directions -- a new unprovable union fires because the gap must not grow in silence, and a pinned union becoming provable fires because a stale pin is debt claimed that no longer exists. REOPENING DOOR, named and undated: the full chain, trap-first, with the fourth family member (the provenance of a propagated constraint: it must come from the schema object immediately enclosing that exact `oneOf`, in both baseline and candidate) written into the trap before any of it is implemented, and the `$ref` hop reviewed as its own change. |

## Mandatory consequences

- No component may assume a static workflow called "software pack," "marketing pack," or equivalent.
- An agent never receives, by default, the full project history.
- An executor cannot approve its own result alone when independent review is required.
- The owning user can override or ignore gates, but the system records risks, waivers, and subsequent outcomes.
- Model credentials cannot remain accessible in the same sandbox that runs untrusted code.
- The official desktop app cannot use private endpoints unavailable to external clients.
- Every Studio action must be possible via the Runtime's public API/CLI.
- The Event Store cannot be rewritten by the Dreams Engine.
- Agent agreement is advisory; deterministic policy and evidence decide gates.
- A successful retry cannot erase or relabel its earlier failed attempt as first-pass success.
