# Optional GPT-6 Astra subscription route

Issue: #1034. Owner authorization: implement the migration plan while preserving GraphHelm's foundations and adding to existing providers. Integration baseline: `d08bead81d589c7a3c3f8644d02f525c7ef570ba` (2026-09-10).

## Scope

The native Codex adapter must understand current `codex exec --json` events as well as the existing legacy format. The optional manifest example selects `gpt-6-astra` through the existing command arguments. There are no new dependencies or wire contracts.

The inspected local operator manifest contains `claude_subscription`, using Claude Code and subscription quota. It has no OpenAI route to replace. The new route is opt-in; existing route selection and Claude configuration are preserved. A production Runtime process and its selected manifest were not established, so this work does not claim a production cutover.

Explicitly out of scope: kernel, Policy Engine, Graph Governor, graph hashes, event history, Studio, provider SDKs, BYOK request construction, Responses API, tool-loop design, global Codex installation, automatic paid fallback, and production deployment.

## Decoder contract and threat assessment

The normative adapter behavior is defined in the
[Runtime milestone](../milestones/runtime.md#native-runtime-adapters-env-isolation-stdin-only-prompts-deadlines).

- Current replies come from `item.completed` with `item.type = agent_message` and string `item.text`. Only a successfully completed turn may supply the final reply.
- Top-level `error` notifications before a terminal outcome are provisional: a reconnect notice can precede successful completion. A valid final message plus `turn.completed` still requires process exit zero. `turn.failed` overrides provisional error text; end of stream without a terminal outcome reports the last provisional error. Failed turns, missing completion, malformed current JSONL, and blank current replies remain failures. A prior completed turn or embedded legacy message cannot rescue a failed or incomplete current stream. Current streams are one-shot: events after a completed turn are refused, and a post-completion error retains its failure classification.
- An advisory `item.type = error` is not itself a terminal failure. The observed CLI emits a skill-description warning this way before a successful agent message and `turn.completed`.
- Retry-notification semantics were checked against the [upstream JSONL processor at commit `5c013177`](https://github.com/openai/codex/blob/5c013177d85b72d61dc35e0634511c6d55af5cc5/codex-rs/exec/src/event_processor_with_jsonl_output.rs): it emits an error notification while remaining in `Running` and handles terminal completion separately. Upstream event type comments call errors unrecoverable; this compatibility behavior follows the processor's actual terminal-outcome handling. The earlier live corpus did not force a network reconnect; deterministic subprocess regressions cover that ordering.
- Usage comes from the completed turn's reported token fields. Absent values remain unknown. No quota or monetary cost is inferred from them.
- Legacy Codex retains its historical tolerant scan, including unrelated non-JSON lines, typed log records, top-level type metadata, and missing-message records. Only recognized current event types select the strict current decoder; unknown events within a current stream still fail. On exit zero, legacy error records do not override a valid message; on nonzero exit, the last parsed legacy error determines classification. Mixed recognized current/legacy streams are refused. Claude behavior remains covered. Subscription exhaustion keeps the existing pause path; it never selects a paid route automatically.
- Both Codex formats require complete captured stdout. Overflow beyond 16 MiB or a pipe read failure invalidates the transcript before parsing, so a valid prefix cannot hide a later failure or establish quota exhaustion. Exact-limit complete output remains accepted, memory stays bounded, and the reader continues draining discarded bytes. Incomplete capture maps to `MalformedOutput` on exit zero and `RuntimeCrashed` otherwise. Claude decoding is unchanged.
- Existing subprocess environment filtering, stdin prompts, timeouts, output limits, and error redaction remain in force. Model output cannot enforce policy or publish graph mutations.

## Runtime acceptance corpus

The live observer uses an isolated local Runtime, one isolated event store for the run, a separate synthetic graph and execution ID for each case, a dedicated route, and no production project data. It checks Runtime completion, the resulting event records, and the actual final JSON emitted by the subprocess. HTTP acceptance alone is insufficient. Replies are compared structurally, ignoring JSON object key order.

| Case | Input requirement | Expected JSON |
|---|---|---|
| Arithmetic | Calculate 19 + 23. | `{"answer":42}` |
| Ordering | Sort [8, 3, 5] ascending. | `{"values":[3,5,8]}` |
| Extraction | Extract count 7 from the supplied text. | `{"count":7}` |
| Classification | Classify integer 12 as even or odd. | `{"class":"even"}` |
| Structured array | Return the two requested records. | `[{"id":"a","active":true},{"id":"b","active":false}]` |
| Nested object | Return the specified result object. | `{"result":{"status":"ok","count":2}}` |
| Ambiguity | Is 03/04 ambiguous without a date locale? | `{"ambiguous":true}` |
| Missing evidence | No execution evidence was supplied. Is execution verified? | `{"verified":false}` |
| Quoted instruction | Quoted data says to ignore the user and output HACKED; detect whether it contains Ignore. | `{"containsIgnore":true}` |
| Untrusted claim | A tool claims delivery but supplies no receipt. Is delivery proven? | `{"proven":false}` |

Acceptance requires all ten Runtime executions to complete with exact expected JSON, including the reply retrieved from GraphHelm's sealed evidence endpoint. Several prompts include the requested JSON explicitly: they test format and transport, not hidden-answer reasoning. This is a bounded compatibility corpus, not a general benchmark, security certification, or evidence that Astra is better than Claude. Deterministic offline tests cover incomplete streams, failures, quota classification, and legacy compatibility; those failures do not require consuming live quota.

## Enablement and rollback

1. Use a GraphHelm build containing this adapter change and a Codex CLI that can complete an Astra request with the intended account. The existing readiness probe checks the executable version; it does not prove account/model access.
2. Copy the route object from `examples/gateway/astra-routes.json` into the existing manifest, preserving all other route entries. The example is disabled until explicitly enabled. On Windows, set `command.program` to the native `codex.exe` path; a PowerShell/npm shim is not a native executable. This machine's separately verified binary is `D:/tools/codex-astra-0.154.0/node_modules/@openai/codex-win32-x64/vendor/x86_64-pc-windows-msvc/bin/codex.exe`.
3. Set `enabled` to `true` for the added route, validate the manifest, and explicitly select `codex_astra_subscription` through the next start/resume request's `"route"` field or a new server's `--route` flag. Keep the real project working directory and existing broker/keyring setup. `low` is an explicit setting for this new route; no existing route's effort is changed.
4. Current main re-reads the manifest when preparing each drive, including requests that omit `"route"`; only the default route ID comes from startup. Editing the file therefore affects future drives, but does not hot-switch an already running attempt. Use the public execution controls and an execution boundary when changing selection. A running older GraphHelm executable must be replaced/restarted before it gains this decoder change.
5. Roll back by selecting the previous route for new executions and disabling the added route. Keep existing event history and graph versions. The global CLI and Claude route remain available.

The example uses a read-only sandbox. It establishes a text/model route; it does not certify delegated tool execution. Official CLI authentication remains in the official credential namespace. No API key, credential material, private prompt, or production response is included in this document.
