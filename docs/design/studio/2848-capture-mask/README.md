# Captures paint only secrets (#2848)

Static before/after mocks of a journey frame, drawn before the change (the script that drew them is not kept; they are images only).

- `form-before.png`: a form as a capture showed it: every field, plain or secret, covered by a magenta block.
- `form-after.png`: the same form as a capture shows it now. Search, e-mail and note fields keep their content and get a magenta outline. The password field, the field filled from a flow secret and the visible echo of that secret are painted magenta (the outline also rings the painted fields).
- `studio-before.png`: the Studio's Proof screen with its journey search box covered by a magenta block in a frame.
- `studio-after.png`: the same screen with the search box readable inside its outline.
- `real-after.png`: build evidence, not part of the approved set. It is a capture made by the built driver (`tools/journey-driver/driver.mjs`) on the driver's own fixture page `/fields`: a plain search, e-mail and note field show their text with an outline, an empty contenteditable is outlined, a password field and a field filled from a secret are painted, and so is the echo of that secret.

Rule drawn: a capture paints only password fields, fields the flow filled from a `secret`, visible text equal to a known secret, and embedded frames; every other editable field is outlined, not covered.

Accepted trade, stated to the owner before approval: a value typed in a plain field (for example an e-mail address) becomes visible in captures. A flow that handles something sensitive must mark it as a `secret`.

Author decisions on top of the approved rule, from the review of the build (labelled as such, not part of the approved drawing): An editable field (`input`, `textarea`, `[contenteditable="true"]`) shows a known secret when what it draws (its `value`; its `placeholder` while the value is empty, since a placeholder is drawn only then; the text for a contenteditable) and a declared secret, each folded to lowercase letters and digits only (every other character dropped), share a contiguous run of at least min(4, folded secret length) characters. That one rule covers an exact copy, other case, spacing, separators (`4242-4242-4242-4242`, `sk_PROBE_123456`), an ellipsis at either end and a label plus a cut (`key: sk-PROBE-12…`). A folded secret of length 0 never matches. Over-painting is the accepted direction: a plain value that shares 4 letters or digits with a secret is painted too (for example the value `be 2848` for a secret ending `probe-2848`). Field text is compared up to 4096 characters; a longer field is painted, not skipped. Such a field is painted. The paint is computed for the editable fields read in one pass and applied to those very elements (a temporary `data-graphhelm-paint` attribute, removed with the outline), never by re-resolving a position. A field whose value cannot be read is painted. Around the screenshot the editable-field list is taken again, and the same read is repeated: if the list differs, or any field that was outlined now shows a secret (a page wrote it in after the read), the whole read-and-capture is repeated once on the new DOM, and a second difference refuses with `driver.capture_refused` and keeps no image. One retry is the bound: a page that keeps changing cannot be given a mask known to fit it, and an endless retry could hang a flow; a refusal is the safe failure because the flow fails loudly where an unpainted secret would pass silently. Known limits, stated and not solved: a page that overrides the value getter to lie can hide a value from this check; a transformed echo (upper-cased, truncated) in a non-editable element is matched only as `getByText` matches it, as before this change; and a value the page draws that is not what the field holds (a masked or formatted overlay) is outside what this reads.

Not drawn in the mocks, decided in the build: a text field whose `autocomplete` names a credential or payment value (`current-password`, `new-password`, `one-time-code`, `cc-number`, `cc-csc`, `cc-exp`, `cc-exp-month`, `cc-exp-year`) is painted too, as a cheap guard for a secret typed into a `type=text` field.
